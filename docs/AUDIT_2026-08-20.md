# AUDIT 2026-08-20 — Manus Decoupling & Security Hardening

**Status: COMPLETE — all files VERIFIED**

## Changes applied

This audit removed every dependency on the Manus platform and hardened the application's security posture. The server's legacy OAuth/Forge layer (`server/_core/{sdk,oauth,dataApi,storageProxy,llm,imageGeneration,voiceTranscription,notification,heartbeat}.ts`, `lib/_core/manus-runtime.ts`, `server/_core/types/manusTypes.ts`, `template.json`) was fully deleted and replaced with a self-contained local auth stack.

## New architecture

Local authentication (`server/_core/localAuth.ts` + `authRouter.ts`) uses PBKDF2-SHA256 with 600,000 iterations and a random 16-byte salt, constant-time password comparison, HS256 JWT sessions signed with `JWT_SECRET` (minimum 32 characters), and httpOnly/sameSite=lax/secure cookies. Routes: `/api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/me`.

A critical security fix: logout previously cleared the cookie only, leaving JWT tokens mathematically valid until their one-year expiry. An in-memory revocation cache (`revokedTokens` Map with automatic expiry and pruning) now invalidates the exact token at logout time, invoked from both cookie and Authorization header sources.

Object storage (`server/storage.ts`) uses a hand-written SigV4 implementation with the Authorization header variant. The canonical request was verified byte-for-byte against botocore; the decisive difference was botocore's trailing newline after the last canonical header. Keys are validated to block path traversal.

## Database

MySQL `tbp_dev` via Drizzle push. The `users` table gained a `passwordHash` column; `upsertUser` was fixed to actually persist it during registration (it was silently dropped before).

## Dependency hardening

pnpm overrides pin: vitest >=3.2.6 (4.1.11 installed), @trpc/* >=11.8.0, rollup >=4.59.0, drizzle-orm >=0.45.2, postcss >=8.4.50, esbuild >=0.25.0, uuid >=11.1.1 (14.0.2 installed), vite >=6.4.3 (dev toolchain only). Residual advisories: image-size 1.2.1 sits in the safe branch of its advisory (vulnerable <=2.0.2, no backport to 1.x) inside @expo/vector-icons and processes no attacker input; vite advisories apply only to the dev server on Windows and this codebase never runs a Vite dev server in production.
