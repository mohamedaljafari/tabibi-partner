# طبيب شريك — تطبيق مقدم الخدمة

تطبيق الهاتف الخاص بمقدمي الخدمات الصحية في منصة **طبيبي** للرعاية الصحية المنزلية في ليبيا. يتيح التطبيق للطبيب والممرض والاختصاصي (وغيرهم من مقدمي الخدمات) إنشاء حسابه واستكمال ملفه المهني وإدارة خدماته ومواعيده واستقبال طلبات المرضى الواردة وقبولها أو رفضها والتواصل معهم ومراجعة أرباحهم المحاسبية.

## نظرة عامة على النظام

يتكون النظام من ثلاثة أجزاء مرتبطة معًا عبر مخزن بيانات محلي مشترك على الجهاز، ويكمل تطبيق مقدم الخدمة رحلة الخدمة التي يبدأها المريض من تطبيق طبيبي:

| الجزء | المستودع | الوظيفة |
|-------|----------|---------|
| تطبيق مقدم الخدمة (هذا المستودع) | [tabibi-partner](https://github.com/mohamedaljafari/tabibi-partner) | استقبال الطلبات، قبولها ورفضها، إدارة الخدمات والمواعيد، الدردشة، الأرباح |
| تطبيق المريض | [tabibi-mobile](https://github.com/mohamedaljafari/tabibi-mobile) | البحث عن مقدمي الخدمات، الطلب، الدفع، الدردشة، المحفظة |
| لوحة تحكم الإدارة | داخل تطبيق المريض عبر المسار `/admin` | مراجعة مستندات مقدم الخدمة وتفعيل الحساب، إدارة الإعلانات والخدمات والمحفظات |

## رحلة مقدم الخدمة

يبدأ مقدم الخدمة بالتسجيل (الاسم، الصفة المهنية: طبيب/دكتور/ممرض/اختصاصي، رقم الهاتف، كلمة المرور)، ثم يستكمل ملفه المهني باختيار تخصصاته (يمكن اختيار أكثر من تخصص)، ورفع مستنداته (الشهادة، إذن المزاولة، ترخيص العمل — تُراجع من الإدارة فقط ولا تظهر للمريض)، وإضافة نبذة وسنوات الخبرة، وإدارة خدماته (اسم الخدمة وسعرها ومدتها مع اقتراح خدمات جاهزة حسب التخصص وإمكانية إضافة خدمات مخصصة)، وإدارة مواعيده (متاح الآن أو جدولة حسب الأيام والتوقيتات).

بعد ذلك تظهر الطلبات الواردة في تبويب الطلبات مع تفاصيل الخدمة المطلوبة والعنوان وطريقة الدفع التي اختارها المريض (نقدي بعد إتمام الخدمة، أو إلكتروني بعد القبول). عند قبول الطلب تُفتح المحادثة تلقائيًا بين الطرفين ويُشعر المريض بالقبول، وعند رفضه يُشعر بالرفض وتُحذف بقية الطلبات المفتوحة على العرض. وعند إتمام الخدمة تُسجّل في محفظة مقدم الخدمة قيد "مستحق له" ويصله إشعار.

```
│   ├── login.tsx        # تسجيل الدخول

│   └── chat.tsx         # الدردشة مع المريض
├── lib/                 # المكتبات المنطقية
│   ├── provider-auth.ts     # المصادقة والملف المهني
│   ├── provider-services.ts # الخدمات والمواعيد
│   ├── incoming-requests.ts # الطلبات الواردة وحالاتها
│   ├── chat.ts              # الدردشة والمرفقات (مشتركة مع المريض)
│   ├── wallets.ts           # المحفظة المحاسبية (مشتركة)
│   └── notifications.ts     # الإشعارات
├── components/          # المكونات المشتركة (chat-attachment-bar)
├── tests/               # اختبارات Vitest (دورة خدمة كاملة من 31 اختبارًا)
└── .github/workflows/   # عمليات GitHub Actions (CI)
```

## التثبيت والتشغيل

يتطلب المشروع Node.js 22 وpnpm 9. أنشئ المستودع محليًا ثم ثبّت الحزم وشغّل خادم التطوير:

```bash
git clone https://github.com/mohamedaljafari/tabibi-partner.git
cd tabibi-partner
pnpm install
pnpm dev
```

يفتح خادم التطوير معاينة ويب على المنفذ 8082. لتجربة التطبيق على هاتفك الفعلي، امسح رمز QR الذي يولّده Expo عبر تطبيق **Expo Go** (متاح في App Store وGoogle Play). لتجربة الترابط الكامل بين التطبيقين، افتح معرضي المريض والشريك معًا على نفس الجهاز.

```bash
pnpm test      # تشغيل الاختبارات
pnpm check     # التحقق من TypeScript
```

## التخزين المحلي المشترك

يعتمد التطبيق على المفاتيح نفسها التي يستخدمها تطبيق المريض ليظهرا كأنهما متصلان بخلفية واحدة:

| المفتاح | المحتوى |
|---------|---------|
| `provider_accounts_v1` | حسابات مقدمي الخدمات وحالاتها |
| `service_requests_v1` | الطلبات المشتركة بين الطرفين |
| `chat_threads_v1` / `chat_messages_v1` | المحادثات ورسائلها ومرفقاتها |
| `wallets_v1` | قيود المحفظة المحاسبية |
| `notifications_v1` | الإشعارات |
| `ratings_v1` | التقييمات |

## تفعيل الحساب

بعد التسجيل واستكمال الملف المهني تبقى حالة الحساب "بانتظار المراجعة" حتى تراجع الإدارة مستندات مقدم الخدمة من لوحة التحكم. بعد التفعيل يظهر للشريك في ملفه الشخصي. لا تظهر بياناته للمستفيدين إلا بعد التفعيل، وتظهر شارة "موثّق" على بطاقته في بحث المريض.

## بناء تطبيق الجوال ونشره

يُنشأ ملف APK عبر زر **Publish** في واجهة المشروع على منصة Manus، والتي تبني النسخة النهائية وتولّد ملف APK قابل للتثبيت على Android. يُفضَّل استخدام هذه الآلية بدل البناء اليدوي في بيئة التطوير لتجنب استهلاك الموارد.
